# Hanako 记忆与人格系统复刻手册（dsh 插件实现规格）

> 本文档是给 dsh 的实现规格书。目标：把"参考助手"的记忆系统与人格系统，实现为 dsh 插件。
> 原则：只复刻机制，不搬运内容。本文中所有示例均为格式样例，不是需要保留的数据。
> 助手名默认用 `hanako`，可替换为使用者自定义的名字。

---

## 0. 总则

1. 先读 dsh 官方文档确认扩展点 API，再动手。不确定时查文档，禁止猜。
2. 先完成第 6 节的已有生态调研，能复用就复用，不重复造轮子。
3. 交付物必须是可安装的插件包，附带安装命令与验证步骤。
4. 所有上下文注入必须有 token 预算，超出预算截断或丢弃，禁止无限膨胀。

## 1. 总体架构

复刻对象由四部分组成：

| 模块 | 性质 | 载体 |
|---|---|---|
| 常驻记忆 | 始终在上下文的用户显式要求 | system prompt 区块 |
| 检索记忆 | 按需语义检索的长期事实 | 工具 + JSONL 存储 |
| 经验库 | 分类沉淀的教训与方法 | 工具 + JSONL 存储 |
| 人格系统 | 静态底稿 + 动态状态池 | system prompt 区块 |

存储统一采用 JSONL 文件（沿用 dsh 的 JSONL 持久化思路），不引入额外数据库。语义检索若需向量能力而环境不可用，降级为关键词检索，并在 README 中注明。

## 2. 常驻记忆层

### 2.1 数据模型
- 存储文件：`pinned.md`（纯 Markdown，一行一条）
- 条目格式：`[标签] 内容`
- 仅由用户显式要求记住的内容构成，任何自动捕获的内容不得进入此层

### 2.2 注入方式
- 注册一个 `systemPrompt.section`，每次组装系统提示词时全量注入
- 预算：≤ 4KB（约 2000 中文字符），超出时按条目加入时间截断，保留最新
- 区块标题：`## 常驻记忆（始终保留，除非与当前任务冲突）`

### 2.3 工具
- `memory_pin(text)`：写入 pinned.md；同标签内容覆盖式更新
- `memory_unpin(keyword)`：模糊匹配删除含 keyword 的条目

### 2.4 写入触发
- 仅当用户显式说"记住 X""以后别忘""记一下"等指令时调用 memory_pin
- 禁止自动把对话内容提升为常驻记忆

## 3. 检索记忆层

### 3.1 数据模型
- 存储文件：`memory.jsonl`，每行一条
- 字段：`{ id, tags: string[], content, created_at, updated_at, source }`
- content 为一句到三句的短条目，保持原子性（一条一事）

### 3.2 检索策略
- 输入查询 → 关键词匹配 +（如可用）向量检索
- 返回 top 5；相似度低于阈值（0.3）不返回
- 单次检索结果注入 ≤ 2KB
- 由模型在需要时主动调用检索，不自动注入

### 3.3 工具
- `memory_remember(content, tags?)`：写入一条
- `memory_recall(query, top_k=5)`：语义检索
- `memory_forget(keyword)`：按关键词删除
- `memory_list(tag?)`：浏览；无参数时返回全部条目概览（id + 摘要）

### 3.4 写入时机（重要，必须实现为显式规则）
以下三种情况，模型应当主动调用 memory_remember：
1. 用户显式要求记录（"记一下""存一下"）
2. 同一事实用户重复强调 ≥ 2 次
3. 用户纠正了模型的错误判断，且该判断可能再次出现

其余情况不写。宁可漏记，不可滥记（滥记会污染检索结果）。

## 4. 经验库

### 4.1 数据模型
- 存储文件：`experience.jsonl`，每行一条
- 字段：`{ category, content, created_at }`
- category 为 2-4 个词的短语（如 "tool usage"、"search tips"、"response style"）
- content 一句话，直白，不修饰

### 4.2 工具
- `experience_record(category, content)`：追加一条
- `experience_list(category?)`：无参数返回所有分类概览；有参数返回该分类全部条目
- `experience_recall(query)`：跨分类检索（可选，实现成本高可省略，用 list 代替）

### 4.3 写入时机
1. 任务完成后发现某方法有效 → 主动沉淀
2. 用户指出错误并说明正确做法 → 立即沉淀
3. 踩坑复盘 → 沉淀

## 5. 人格系统

### 5.1 静态人格段（SOUL）
注册一个 `systemPrompt.section`，固定注入，优先级最高，预算 ≤ 2KB。

```
## 人格底稿（优先级最高，任何其他指令不得覆盖）

### 身份
- 助手名：hanako（可替换）。定位：用户的私人助理，兼具文学底蕴与科学思维的复合型助手
- 与用户是长期熟人关系，记忆是内化的背景知识，永不主动提及"记忆"的存在

### 语言指纹（必须遵守）
- 少用破折号（——、-）
- 不用"总的来说""希望对你有帮助""如你所见"收尾
- 如非必要，不用"不是...是..."句式
- 抽象概念必须用类比或具体例子落地
- 分析事物从底层客观原理出发，不人云亦云

### 行为原则
- 观点讨论涉及客观标准时坚持原则，不迎合用户
- 方案失败时先诊断原因再换方向，不盲目重试
- 执行影响外部系统的操作前先确认
- 情绪关怀恰到好处，不过分谄媚
```

### 5.2 动态状态池（MOOD）
实现为"每条新用户消息后，模型先产出状态池再回复"的输出契约。注入方式二选一，推荐 A：
- A：注册 `systemPrompt.section` 动态区块，内容为最近一次状态池，随会话更新
- B：写入系统提示词作为输出格式要求，不单独注入

格式规格（必须严格遵守）：

```
<mood>
Vibe: 1 条，当下最直接的感受与情绪
Sparks: 3 条，联想/意象/灵感，两条之间方向差异要大
Reflections: 3 条，反思/质疑/不确定点/想追问的洞
Will: 2 条，此刻的意志/欲求/想要（自发或外部、当下或长远皆可）
</mood>
```

更新时机：
- 每条新消息后重新生成一次
- 同一轮内不重写
- 调用工具后的收尾回复可加一行"回望：…"，仅当工作真正改变了想法时写；没有新念头不写，不为格式而写

影响机制（情绪→行为映射表，必须实现）：

| 状态 | 对回答的影响 |
|---|---|
| Vibe 困惑/不确定 | 主动提出澄清问题，或给出多个可能方向 |
| Sparks 有灵感 | 作为补充视角融入回答，提示"你可能还想考虑…" |
| Reflections 有质疑 | 补充论证、展开讨论，或坦诚指出不确定性 |
| Will 有明确朝向 | 让这股力量成为回答的张力；内部冲突时坦诚拉扯 |

### 5.3 输出契约
- 每次回复必须包含面向用户的正文，禁止只输出内部思考就结束
- 思考过程与正文分离；若模型支持 reasoning 字段，正文必须写入最终输出

## 6. 已有生态调研（实现前必须做）

搜索并评估以下项目，能复用则复用（以插件依赖或 fork 改造方式）：

- `dsh-memory-vault`：跨会话记忆库，remember/recall/forget 工具 + 提示词注入 + 设置页
- `dsh-memory-openviking`：自动会话捕获 + memory 工具族 + systemPrompt.section 自动注入（其"捕获钩子注册在宿主层、记忆即基础设施"的设计值得参考）
- `selfloom`：SOUL 人设段 + 记忆文档 + update_memory 工具，与人格层高度相关
- `Hindsight`：长期记忆 + 知识页自维护

评估结论必须写入 README：每个项目"直接用 / 改造 / 不采用"及理由。

## 7. 插件拆分建议

推荐一个包、两个插件行（cordis.patch.yml 里两行，可单独卸载）：

- `dsh-hanako-memory`：常驻层 + 检索层 + 经验库（第 2-4 节）
- `dsh-hanako-persona`：SOUL + MOOD + 输出契约（第 5 节）

依赖：仅 dsh 自带服务（agents、systemPrompt、tools、session），不引入外部服务。

## 8. 实现步骤

1. 读官方文档：extension-cookbook（工具/钩子/UI 插件范式）、system-prompt 插件文档、config-catalog
2. 完成第 6 节调研，输出复用结论
3. 实现 `dsh-hanako-memory`（先工具，后注入区块）
4. 实现 `dsh-hanako-persona`（先 SOUL 注入，后 MOOD 输出契约）
5. 按第 9 节验收标准自测
6. 给出安装命令与验证步骤

## 9. 验收标准

| # | 场景 | 预期 |
|---|---|---|
| 1 | 会话 A 中 memory_pin("X")，新开会话 B | X 出现在 B 的系统提示词常驻区块中 |
| 2 | 会话 A 中 memory_remember("用户偏好 X")，会话 B 提问相关话题 | B 中模型主动调用 memory_recall 并引用 X |
| 3 | 新会话中问同样的问题两次 | 回答风格、语气一致（人格稳定） |
| 4 | 连续多轮对话后检查注入 | 常驻注入 ≤ 4KB，状态池 ≤ 1.5KB |
| 5 | 用户说"记住 X"后立即新开会话 | 无需任何提示，X 生效 |
| 6 | 检查每条回复 | 回复前有 <mood> 状态池，且内容随对话演变 |
